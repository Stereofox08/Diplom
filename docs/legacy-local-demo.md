# ByteStore — информационная система интернет-магазина компьютерных комплектующих с ИИ-подбором

Дипломный проект (ВКР): **«Разработка информационной системы интернет-магазина компьютерных комплектующих ByteStore с применением технологий искусственного интеллекта для подбора компьютерных комплектующих»**.

Магазин работает в **тенге (₸, KZT)**; цены каталога заданы в казахстанском прайсовом диапазоне, доставка по Алматы, Астане и регионам Казахстана.

Проект реализован как **клиентское веб-приложение на чистом HTML/CSS/JavaScript** без сборщиков и сторонних библиотек: открывается двойным кликом по `index.html` или через любой статический сервер. Сбор данных — `localStorage` через слой-репозиторий `BS.db`, что позволяет заменить хранилище на REST API без переписывания интерфейса.

## 3. Искусственный интеллект: как это работает

Реализованы **два независимых уровня** — это принципиальное решение проекта: демонстрация работает даже без интернета и без API-ключа.

### 3.1. Экспертный движок (офлайн, всегда доступен)

`js/ai/advisor.js` — детерминированный алгоритм подбора + 10 правил совместимости:

1. сокет процессора = сокет материнской платы;
2. тип памяти (DDR4/DDR5) совпадает с платой;
3. количество модулей памяти ≤ числа слотов;
4. суммарный объём памяти ≤ максимума платы;
5. форм-фактор платы поддерживается корпусом;
6. длина видеокарты ≤ максимальной длины в корпусе;
7. высота воздушного кулера ≤ допустимой в корпусе;
8. TDP кулера ≥ TDP процессора (с запасом), сокет кулера поддерживается;
9. мощность БП ≥ пикового потребления с запасом 25–30 % (учитывается и рекомендация производителя видеокарты);
10. наличие дискретной графики, если у процессора нет встроенной.

Алгоритм сборки: распределение бюджета по слотам весами задач → выбор деталей по метрике «производительность на тенге» → подгонка под бюджет → вложение остатка (апгрейд видеокарты, процессора, памяти, SSD) → финальная проверка совместимости. Дополнительно рассчитывается пиковое энергопотребление, рекомендуемый БП и прогноз FPS для 1080p/1440p/4K с определением «узкого места» сборки.

### 3.2. ИИ-надстройка (OpenRouter, бесплатные модели) — полностью автоматическая

Администратору нужно сделать **только одно действие** — вставить API-ключ OpenRouter в админ-панели.
Дальше система работает сама, без выбора модели вручную:

1. **Получение списка** — `GET /api/v1/models`, фильтрация моделей с нулевой ценой и суффиксом `:free`
   (платные модели отбрасываются), сортировка по приоритету семейств и объёму контекста.
2. **Проверка «здесь и сейчас»** — по 4 лучшим кандидатам одновременно отправляется короткий
   запрос-проба (`ping`, 8 токенов, таймаут 12 с). Живой считается только та модель, которая реально ответила.
3. **Активация** — первой по приоритету живой модели присваивается статус активной, сохраняются время
   проверки и длина контекста. Проверка кэшируется на 30 минут (и выполняется заново после смены ключа).
4. **Автопереключение (failover)** — если активная модель в момент запроса недоступна (429, 404, 5xx,
   таймаут, обрыв сети), запрос автоматически уходит на следующую живую модель, а новая активная
   фиксируется в базе. Сбойная модель «остывает» 10 минут и не используется в этот период.
5. **Повторы и тонкости** — до 3 моделей на один запрос; если модель не поддерживает JSON-режим
   (`response_format`), запрос повторяется без него; при полной недоступности ИИ отвечает встроенный
   экспертный движок, а пользователь видит обычный ответ без технических сообщений.

**Что видит покупатель:** только нейтральный статус «ИИ-ассистент ByteStore» в конфигураторе и чате.
Сообщений вида «подключите API-ключ» или «выберите модель» в пользовательском интерфейсе нет —
все подробности (активная модель, список найденных моделей, время проверки, «остывающие» модели,
статистика токенов) доступны только в админ-панели.

Ключ хранится в базе магазина (`localStorage`) и передаётся напрямую в OpenRouter.
Управлять моделью, температурой, лимитом токенов и подсказками ассистента из интерфейса не требуется:
разумные значения задаются в `db.settings().ai` и используются автоматически.

## 5. Модель данных (`localStorage` → ключ `bs:db`)

```js
{
  version, categories[], products[], users[], reviews[], orders[],
  promos[], carts{userId|guest}, favorites{userId|guest}, events[], visits[],
  admin{login, passHash, salt, failedAttempts, lockedUntil},
  settings{ deliveryCost, freeDeliveryFrom, ai{apiKey, model, temperature, …} },
  audit[]                      // журнал действий администратора
}
```

Товар: `id, sku, name, categoryId, brand, price, oldPrice, cost, stock, rating, reviews, sales, badges[], key[], specs{}, description, image, status, views, createdAt`.
Заказ: `number (BS-24001), items[], subtotal, discount, deliveryCost, total, promoCode, payment, deliveryType, status, source, history[], customer{}`.
Отзыв: `productId, userId, author, rating, text, pros, cons, status (pending|published|rejected), reply, likes, verified, createdAt`.

Пароли пользователей и администратора хранятся в виде соли + SHA-256 (WebCrypto с резервным FNV-хэшем). Вход администратора блокируется на 5 минут после 5 неудачных попыток.

## 6. Тестирование

Помимо ручной проверки интерфейса, в проекте есть headless-тесты, которые выполнялись движком JavaScriptCore (`jsc`) со стабами браузерных API:

* **Синтаксическая проверка** всех 23 JS-файлов (`new Function(source)`).
* **Функциональный тест ядра** — 60+ проверок: генерация демо-данных (60 товаров, 11 категорий, 210 заказов за 90 дней), поиск и фильтрация, корзина и промокоды, расчёт итогов, подбор сборок в пяти сценариях (игровой 1080p/1440p, рендер 4K, офис, стриминг с монитором) с контролем попадания в бюджет, совместимости, достаточности БП и заполненности слотов, обнаружение конфликтов в заведомо несовместимой сборке, интенты бота, аналитика дашборда (выручка, серии, воронка, конверсия, маржа), модерация отзывов, CRUD товаров и категорий.
* **Smoke-тест интерфейса** — загрузка всех модулей, рендер карточек товара/категории/отзыва/заказа, шапки, подвала, корзины-drawer, проверка регистрации всех модулей страниц, модуля админки, графиков, чат-виджета и клиента OpenRouter (включая нейтральность статуса для витрины).
* **Тест автоподбора модели** — с имитацией OpenRouter (локальный мок `fetch`): проверка фильтрации платных моделей, автоматического выбора самой приоритетной живой модели, записи времени проверки, автоматического переключения при ошибке 429, «остывания» сбойной модели, полного резерва при недоступности всех моделей, восстановления после сбоя и админской перепроверки.
* **Тест переноса сборки из чата в конфигуратор** — 47 проверок: сопоставление всех категорий каталога со слотами сборки, разбор состава сборки из текста ИИ (по названиям и по `id`), разложение товаров по слотам с отсечением дублей, формирование сборки ботом прямо в чате, отрисовка кнопки «Добавить в конфигуратор», сохранение перенесённых комплектующих в хранилище конфигуратора и восстановление полного совместимого комплекта на вкладке ручной сборки (включая монитор, клавиатуру, мышь и гарнитуру как дополнительный блок), а также распознавание задач и разрешения из свободного текста покупателя.

Проверки выполнялись командами:

```bash
jsc /tmp/check_all.js     # синтаксис всех модулей
jsc /tmp/bs_test.js       # логика ядра, подбора, заказов, аналитики
jsc /tmp/bs_ai.js         # автоматический выбор модели и автопереключение
jsc /tmp/bs_smoke.js      # загрузка модулей и рендер компонентов
jsc /tmp/bs_transfer.js   # перенос сборки из чата в конфигуратор
```

## 9. Примечания для защиты

* **Валюта — тенге (₸).** Форматирование сумм вынесено в `BS.util.money()` / `BS.util.kilo()`, символ валюты и параметры доставки задаются константами в `BS.util.APP` и `db.settings()`. Цены каталога пересчитаны в казахстанский прайсовый диапазон: сборка уровня Full HD — от 387 000 ₸, игровая 1440p — от 595 000 ₸, станция 4K — около 1 568 000 ₸. Доставка — 2 990 ₸, бесплатно от 250 000 ₸.
* Промокоды: `BYTE10` (−10 % от 280 000 ₸), `START5` (−5 % на первый заказ), `UPGRADE15` (−15 % на сборку от 680 000 ₸), `FREESHIP` (бесплатная доставка от 85 000 ₸).
* Демонстрационные данные (товары, заказы за 90 дней, отзывы, посещаемость) генерируются детерминированно, поэтому графики дашборда наполнены сразу после открытия проекта.
* Все внешние зависимости отсутствуют: изображения товаров, иконки и графики создаются кодом (SVG и canvas), что гарантирует работу при защите без интернета.
* **ИИ настраивается одним действием.** Администратор вставляет только API-ключ OpenRouter — система сама получает список бесплатных моделей, проверяет их живым запросом, выбирает приоритетную рабочую и автоматически переключается на следующую при сбое (код: `js/ai/openrouter.js`, функции `listFreeModels`, `selectModel`, `ensureModel`, `chat`). В пользовательском интерфейсе нет ни выбора модели, ни сообщений о необходимости подключить ключ: покупатель всегда видит «ИИ-ассистент ByteStore».
* Ключ OpenRouter не является обязательным — при его отсутствии и при полной недоступности моделей проект демонстрирует работу экспертного движка: подбор конфигураций, расчёт совместимости и ответы бота остаются полностью функциональными.
