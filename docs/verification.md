## Оставшиеся подключения

Для публичной регистрации и восстановления пароля нужен собственный SMTP-отправитель в Supabase Auth. Сейчас подтверждение e-mail включено; тестовый отправитель Supabase ограничивает адресатов и частоту отправки. Минимум пароля в интерфейсе — 8 символов.

Оплата картой, QR и рассрочка работают в учебном режиме; при получении заказ остаётся неоплаченным. Реальные банковские платежи, прокси внешнего ИИ и общая аналитика посещений не подключены. Корзина и избранное сохраняются на устройстве.

Проверка восстановления учебной оплаты: `tests/demo-payment.cjs` — четыре способа, валидация карты, QR, выбор банка, отсутствие реквизитов карты в заказе. Серверные проверки четырёх способов и повторного запроса выполнены в транзакции с ROLLBACK: тестовые заказы и списание остатков не сохранялись.

22 октября 2026: SMTP Gmail сохранён и проверен после перезагрузки панели. Контрольный запрос восстановления на адрес владельца получил HTTP 200; Auth записал успешное завершение /recover. Пароль пользователя не изменялся. Доставка во входящие отдельно не проверялась.

Проверка исправления подтверждения почты 22 октября 2026: в Supabase сохранён шаблон `supabase/confirm-email.html` с полным адресом `/Diplom/login.html`; этот адрес добавлен в Redirect URLs. Выполнена настоящая регистрация временного Gmail-псевдонима без redirect_to в запросе (включая Referer с корнем домена), письмо получено через Gmail, проверена ссылка из письма, подтверждение вернуло сессию и HTTP 200 на `/Diplom/login.html`. Проверка /auth/v1/user подтвердила адрес, сессия завершена и тестовый аккаунт удалён. Удаление строк `public.profiles` не удаляет учётные записи `auth.users`: для повторной регистрации требуется удалять пользователя через Authentication → Users.
