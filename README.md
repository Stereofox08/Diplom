# ByteStore

Магазин комплектующих на GitHub Pages с общей базой PostgreSQL в Supabase и отдельной админкой для macOS.

Сайт: https://stereofox08.github.io/Diplom/

## Как работает

- Каталог, цены, остатки, категории, промокоды, профили, отзывы и заказы хранятся в PostgreSQL.
- Сайт и приложение используют один API. Изменения в админке попадают в магазин; заказы покупателей доступны администратору.
- Вход — Supabase Auth. Администратор назначается записью в закрытой таблице `private.staff`, а не полем в браузере или редактируемыми метаданными пользователя.
- RLS включён на всех таблицах. Покупатель читает собственный профиль и заказы. Закупочные цены, настройки ИИ и журнал доступны администратору.
- Корзина и избранное пока сохраняются на конкретном устройстве; они не являются серверной базой товаров и заказов.

## Заказы

Оформление требует входа. Сервер сам проверяет товары, цены, остатки и промокод, рассчитывает доставку и сумму. Строки товаров блокируются в определённом порядке, поэтому последнюю единицу нельзя продать одновременно двум покупателям. Списание и заказ фиксируются одной транзакцией.

Для повтора после обрыва связи используется идентификатор запроса. Отмена возвращает остатки один раз. При изменении цен покупатель должен обновить корзину. Конфликт редактирования товара возвращает HTTP 409.

Доступны демонстрационная оплата картой, QR и рассрочка, а также оплата при получении. Выбранный способ и статус сохраняются в общей базе; `paymentMode=demo` обозначает учебный режим. Данные карты остаются только в окне оплаты и не отправляются на сервер. Банковские сервисы не подключены.

## Админка macOS

Исходники: `macos-admin/`. Приложение использует встроенный интерфейс админки и общую базу Supabase. Сборка на Mac с Apple Silicon, macOS 13+, Xcode и Python 3:

```sh
python3 macos-admin/build.py
```

Результат: `macos-admin/dist/ByteStore Admin.app`. Приложение подписывается локальной подписью; для публичного распространения нужна подпись разработчика и нотариальная проверка Apple. Паролей в исходниках нет.

Меню macOS позволяет открыть магазин, обновить данные, экспортировать доступные администратору данные и выйти. JSON-экспорт является снимком данных приложения, а не полной резервной копией PostgreSQL/Auth.

Веб-админка и её ресурсы исключены из публикации Pages через `_config.yml`. Исходники сохранены для сборки приложения.

## Конфигурация и база

`js/cloud/config.js` содержит адрес проекта и публичный publishable key. Он предназначен для клиентских приложений; безопасность обеспечивают права PostgreSQL и RLS. Секретные ключи и пароли в Git не помещаются.

- `supabase/schema.sql` — исходная структура таблиц, функций и прав.
- `supabase/revision.sql` — счётчик изменений и актуальная функция снимка данных; применяется после структуры.
- `supabase/seed.sql` — начальные 60 товаров, 11 категорий и 5 промокодов. Демо-пользователи, заказы и отзывы не импортируются.

Сброс общей базы к демо-данным отключён. Исходная локальная версия описана в `docs/legacy-local-demo.md`; это историческая документация, а не инструкция для текущей версии.

Письма подтверждения и восстановления пароля требуют рабочего отправителя в Supabase Auth. Перед открытием публичной регистрации настройте свой SMTP: встроенная тестовая отправка Supabase имеет ограничения. Пароли обрабатывает Supabase Auth.

ИИ-конфигуратор и чат используют встроенный экспертный подбор. Ключ OpenRouter, если его добавят в админке, не выдаётся посетителям; серверный прокси внешнего ИИ пока не реализован. Между клиентами пока не синхронизируется аналитика посещений.

## Проверки

`tests/shared-database.cjs` проверяет реальный вход, форму редактирования товара, изоляцию заказов, права покупателей, гонку за последнюю единицу, повтор запроса, отмену, отзывы и восстановление сессии. Нужны Playwright 1.62.1, Chrome и JSON-файл с двумя временными покупателями и администратором; файл с паролями хранится вне репозитория. Указывайте отдельный тестовый проект: тест создаёт проверочные заказы и отзывы.

```sh
BYTESTORE_TEST_URL=http://127.0.0.1:8766/ \
BYTESTORE_TEST_ACCOUNTS=/private/path/accounts.json \
node tests/shared-database.cjs
```

Формат файла: `{"users":[{"email":"...","password":"...","admin":true},{"email":"qa-a@...","password":"...","admin":false},{"email":"qa-b@...","password":"...","admin":false}]}`. Сам файл в Git не добавляется. Для проверки приложения используется флаг `--smoke-test` и тот же файл через `BYTESTORE_SMOKE_CREDENTIALS`.
